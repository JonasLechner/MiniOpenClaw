Yes — this is the tldraw/whiteboard-style view of what changed.

Focus: Telegram transport, session binding, cron scheduler, and removal of approval machinery.

Color key

🟥 removed pieces

Telegram User

Sends private chat messages.

Supported commands now:

  • /help
  • /new
  • /session

Telegram Gateway

Polling bot receives updates.

Authorizes allowed user.

Queues per-chat work.

Conversation Binding

Maps:

telegram chat + user
→ sessionId

Persisted in JSON.

Agent Runner

Gateway forwards normal text into the bound session.

No approval interception anymore.

Agent Core

Stays generic.

Runs normal model/tool loop.

Explicit session lookup still fails fast if missing.

Telegram Reply

Response is chunked into Telegram-safe messages and sent back.

Cron Job

Runs on schedule.

Cron Scheduler

Replaced the old due-task/reminder flow.

  • reads scheduled jobs from JSON
  • matches cron expression
  • runs job at most once per minute
  • stores lastRunAt

JSON Task Store

Jobs are persisted in scheduled-tasks.json.

No Telegram commands needed for managing them.

Removed

  • approval store
  • approval service
  • tool-policy gating
  • /approve, /deny, /approvals
  • /remind
  • due-task claim/release flow

Important runtime behavior kept

  • Telegram long-poll can be aborted on shutdown
  • session binding survives restart
  • explicit missing session throws instead of silently creating one
