ABSTRACT

MiniOpenClaw is a minimal long-running personal assistant built to explore what an assistant actually needs in order to be genuinely useful. The project centers on a set of core capabilities: workspace tools, chat-based remote access, durable memory, reusable skills, and proactive background jobs. Tool use is sandboxed by default to keep the system practical as well as safe.

Architecture

Architecture overview

MiniOpenClaw centers on a runtime that connects user sessions, model inference, tools, memory, and background work. It runs a sequential tool-calling loop, supports both Telegram and terminal sessions, queues Telegram messages per chat, streams replies back live, and lets detached jobs send results back into the main session.

Implementation details

We used pi-ai for model-provider integration, while the surrounding runtime and agent loop were built from scratch. Telegram files are stored in the workspace and their paths are passed to the model automatically, while workspace files can also be returned to the user.

Workspace boundary

All agent sessions are bound to a workspace mounted into the sandbox container, so file access, search, and bash stay confined to it rather than reaching unrelated parts of the host system.

Sessions & transport

Telegram and TUI keep separate current sessions. Each Telegram chat is bound to one ongoing local session. Background work uses its own fresh detached session and can report results back into the main conversation.

Prompt assembly

The system prompt is assembled once at session start. It combines core rules, durable context, skills, and environment metadata. user.md and context.md provide persistent human-editable context, while workspace skills are discovered dynamically.

Persistence & compaction

Runs are stored as append-only session logs, and tool events record arguments, durations, and errors. When history grows too large, compaction replaces older messages with a continuation-focused summary, using a safe boundary while protecting the current user prompt.

Workspace search

Workspace search provides cross-session recall through a local full-text index, so the agent can retrieve relevant notes, memory, and project files without carrying everything in prompt context.

Learnings

  • Up-front planning mattered more than expected and reduced rework.
  • Because AI-assisted work can move very quickly in different directions, we needed more direct communication to stay aligned, instead of only interacting through our agents.
  • The prototype still demonstrated how much can be engineered in a short time.
  • /review commands surfaced many bugs, and we experimented with CodeRabbit for AI-assisted code review.
!

Limitations

  • The first memory prototype based on a simple JSON index was unsuccessful.
  • In practice, only inference via Copilot and Codex could be tested extensively.
  • AI subscription limits / not enough tokens.
