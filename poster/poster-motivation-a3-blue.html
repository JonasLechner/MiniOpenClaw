What does an AI assistant
actually need to be effective?

01
ABSTRACT

MiniOpenClaw is a minimal long-running personal assistant. The project explores what an assistant actually needs to be helpful. The system combines workspace tools, Telegram-based remote access, durable memory and memory-management, reusable skills, and proactivity through background jobs and daily summaries. To ensure safety, all tools are sandboxed by default using docker containers.

MiniOpenClaw can read, write, edit, and search your workspace, run terminal commands, and use the web.

Architecture

02
Architecture overview · chat interface, tool execution, memory layers, reusable skills, and background jobs

Transport & session control

Current sessions are tracked separately for TUI and gateway surfaces. Background work can use its own fresh session and write results back into the parent session.

Prompt assembly

The final system prompt is assembled once per agent session. It merges core behavior rules, durable context, skills, and environment metadata. USER.md and context.md provide human-editable persistent context. Workspace skills are discovered dynamically from skills/*/SKILL.md frontmatter.

Loop, transcript & persistence

Each run first appends the user prompt to the session transcript. The runtime executes a sequential tool-calling loop until the model returns a non-tool stop reason. Tool execution events expose arguments, durations, and errors. The result is an append-only session log that preserves the full event history.

Compaction

Compaction runs automatically before oversized turns or manually on request. The current user prompt is protected from pre-loop compaction. A safe boundary is chosen instead of cutting arbitrary messages. Replaced history becomes a continuation-focused summary with goals, constraints, progress, decisions, next steps, and critical context.

Workspace search index

Workspace search provides cross-session recall through a local full-text index. The workspace is indexed into SQLite FTS5 with BM25 ranking and kept fresh by a file watcher, so the agent can retrieve relevant notes, memory, and project files without carrying everything in prompt context.

Telegram media bridge

The Telegram bridge connects chat with workspace artifacts. Incoming images/files can be brought into the workspace for tool use, while replies are streamed back incrementally and can return referenced workspace artifacts to Telegram.
