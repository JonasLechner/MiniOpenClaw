MiniOpenClaw memory implementation

The memory system is a small file-based layer built around markdown documents plus a JSON index. Durable memories live by category, retrieval is keyword-first with light reranking, and session-summary persistence exists in code but is currently disabled in the main agent loop.

Analysis notes

  • Source of truth is sane: markdown remains authoritative, so the index can be rebuilt.
  • Index maintenance is incremental: writes update both the markdown file and index.json.
  • Retrieval is simple but explainable: explicit scoring favors category, exact keyword hits, title hits, then summary/body matches.
  • Session summaries are append-by-rewrite: one file per session is reread, a new turn block is appended, then the file is rewritten.
  • LLM metadata generation is optional: summaries/keywords gracefully fall back when generation fails.
  • Main limitation right now: the agent does not persist session summaries because that call is commented out in src/agent/agent.ts.
  • Likely scaling edge: retrieval rereads shortlisted files, so cost grows with shortlist size and file count.
  • Consistency tradeoff: lazy indexing is easy, but manual edits require rebuildMemoryIndex() to fully resync metadata.
